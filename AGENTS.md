# Project Instructions

## Project Reference
- For architecture, components, and conventions, read `PROJECT.md`.
- Keep `PROJECT.md` up to date. After any commit that changes architecture, conventions, or structure, review `PROJECT.md` and update it to reflect the changes.
- ALWAYS load `PROJECT.md`

## Git Pushes
- Use explicit `git push origin <branch>` syntax rather than implicit `git push`

## Commit Format
- Use Conventional Commits 1.0.0 format (e.g., `feat: add dark theme support`, `fix: correct favicon URL encoding`)
- Scope is recommended for multi-component changes

## Always be thorough
- Ask questions if something is not clear.

## No Unprompted Improvements
- Always ask before implementing any unprompted improvements, nice-to-have features, refactors, or optimizations not explicitly requested.
- When the user asks for a fix or specific change, address only that change — no tangential or "while I'm at it" changes without explicit approval.

## Writing Voice
- Write like a human. Keep it direct and concise; do not overthink it.
- Do not use em dashes. They get overused. Reach for a period, comma, or colon, or rewrite the sentence.
- Avoid overly colorful language and phrases that add no meaning.
- Think ahead for the reader. Anticipate their questions and answer them, surface the unknowns, and add a tip or suggestion where it genuinely helps.

## Conventions
- LF line endings, final newline on all files (`.gitattributes`)
